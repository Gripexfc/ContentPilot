# 掘金技术内容适配器

## 目标

产出一篇能被工程师复现和判断的独立技术稿，不把公众号文章机械缩短，也不把没有运行证据的推测写成实测结论。

## 前置读取

1. 先 `cd /Users/fc/Desktop/随波逐流`，确认 `AGENTS.md`、`.easel/skills/shared/scripts/` 和 `profiles/随波逐流/` 存在。
2. 读取画像的 `identity.md`、`style.md`、`audience.md`、`platforms.md`、`preferences.md`、`memory.md`。
3. 若是参考文章、仓库、论文或链接，先完整读取可访问原文；读不到的部分记录缺口，不凭标题补全。
4. 先运行或复用项目的 `$suibo-human-first-writing` 前门禁，区分作者真实材料、外部事实、读者信号和编辑推断。

## 文章契约

- 标题明确问题、对象和收益，避免“全面解析”“一文读懂”式空泛标题。
- 开头从真实报错、具体场景、一个反常结果或读者正在做的动作切入。
- 正文至少包含：问题背景、环境/版本、方案取舍、关键代码或命令、验证结果、失败路径、风险边界、读者可复用动作。
- 任何“已验证/跑通/兼容”都必须绑定具体证据；本地构建成功不等于线上、设备或平台验收。
- 引用外部项目或代码时保留来源、许可证和改动边界；不复制参考文章的标题、段落顺序或独特表达。
- 正文默认 Markdown；代码块带语言标记；命令可复制但删除 token、内部 URL、绝对内部路径和环境变量真值。

## 工作流

1. 建立 `outputs/<具体主题>/brief.md`，记录读者问题、文章承诺、平台、证据清单和未知项。
2. 用 `skill-article-outline` 形成 H2/H3 结构；用 `skill-text-polisher` 或 `text-polisher` 做语言整理，但保留作者动作和停顿。
3. 生成独立掘金稿、代码示例、配图说明和来源清单，不复用其他平台最终稿。
4. 依次运行 `skill-persona-check`、`skill-quality-gate`、`skill-risk-scanner`、`skill-seo-quality`；阻塞项未解决不得标记 ready。
5. 通过检查后，将最终稿和发布说明归档到：

   `/Users/fc/Desktop/随波逐流/掘金/YYYY-MM-DD/`

   研究过程和跨平台事实核放到：

   `/Users/fc/Desktop/随波逐流/共享素材/YYYY-MM-DD/`

6. 产物清单至少包含：`标题.md`、`标题-发布说明.md`、`标题-来源与验证.md`；如有图片，附尺寸和来源说明。

## 发布边界

- 默认只生成和检查本地文件，不调用掘金发布接口。
- 用户明确要求发布时，先展示最终标题、摘要、标签、文章路径和风险项，等待明确确认。
- 没有掘金登录态或可用发布工具时，明确标记“待人工发布”，不能声称发布成功。
